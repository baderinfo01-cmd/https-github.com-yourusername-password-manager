# تحويل البرنامج إلى ملف تثبيت `.exe` — خطوة بخطوة

> الأفضل أن تبني على **ويندوز** نفسه (الجهاز الذي سيُبنى عليه ملف التثبيت). البناء من لينكس/ماك لويندوز يحتاج برنامج Wine.

## 1) التجهيز (مرة واحدة)
1. ثبّت **Node.js 22 LTS أو أحدث** من https://nodejs.org (اختر النسخة LTS، ووافق على كل الخيارات الافتراضية).
2. افتح **PowerShell** داخل مجلد المشروع (في المجلد: Shift + كليك يمين ← "Open PowerShell window here").
3. تحقق: `node -v` و `npm -v` يعرضان أرقام الإصدارات.
4. ثبّت الحزم: `npm install` (قد يستغرق دقائق، يحتاج إنترنت).

## 2) أيقونة البرنامج
الأيقونة الحالية في `build/icon.png` (512×512). لاستبدالها بشعارك: ضع صورة PNG مربعة **256×256 أو أكبر** بنفس الاسم `build/icon.png`. يحوّلها البنّاء تلقائياً إلى `.ico`.

## 3) ضبط معلومات النسخة
- في `package.json`: غيّر `"version"` (مثلاً `3.0.1`) في كل إصدار جديد. يظهر الرقم في اسم ملف التثبيت.
- في `src/config/branding.ts`: اسم البرنامج وبريد التواصل والموقع الظاهرة داخل البرنامج.

## 4) أنشئ ملف التثبيت
```
npm run test         # (اختياري) اختبارات التشفير: يجب أن تنجح كلها
npm run typecheck    # (اختياري) فحص الأخطاء
npm run dist
```
ماذا يحدث؟ 1) `next build` يبني الواجهة في مجلد `out/` 2) `electron-builder` يغلّفها مع Electron ويصنع المثبّت.

النتيجة:
```
dist\Template App-Setup-1.0.0.exe     ← هذا ما تعطيه للزبون
dist\win-unpacked\                                  ← نسخة غير مثبّتة للتجربة السريعة
```
حجم الملف عادةً بين 80 و110 ميغابايت (معظمه محرك Electron). تأكدت أن كود البرنامج نفسه صغير (~14 ميغابايت) بعد إصلاح إعدادات التغليف.

## 5) جرّب قبل التسليم (قائمة فحص)
1. شغّل `Setup.exe` وثبّت. يجب أن تظهر نافذة **تفعيل الترخيص** (لأن النسخة المثبّتة تطلب ترخيصاً).
2. أدخل كود تفعيل صالح من لوحتك ← يفتح البرنامج.
3. أنشئ كلمة المرور الرئيسية، أضف حساباً، أغلق البرنامج وافتحه: تظهر شاشة الدخول وتبقى بياناتك.
4. جرّب كلمة مرور خاطئة: يجب أن تُرفض.
5. جرّب الكود نفسه على جهاز ثانٍ: يجب أن يُرفض (انظر `LICENSE-AR.md`).

## 6) التوقيع الرقمي (موصى به بشدة)
ملف غير موقّع يُظهر تحذير **Windows SmartScreen** ("Windows protected your PC") وقد تحجبه مضادات الفيروسات.
- اشترِ شهادة **Code Signing** (من DigiCert أو Sectigo أو SSL.com، وهناك خيارات أرخص كـ Azure Trusted Signing).
- ثم أضف لـ `package.json` داخل `build.win` أو استخدم متغيرات البيئة `CSC_LINK` و `CSC_KEY_PASSWORD` قبل `npm run dist`.
- بدون شهادة: يعمل البرنامج، ويضغط المستخدم "More info ← Run anyway".

## 7) التحديثات
لكل إصدار جديد: ارفع الرقم في `package.json` ← `npm run dist` ← أرسل المثبّت الجديد. يمكن للزبون التثبيت فوق القديم، وتبقى بياناته وترخيصه (مخزّنة في مجلد بيانات المستخدم وليس في مجلد البرنامج).

## 8) أين تُحفظ البيانات؟
- **الخزنة المشفرة والترخيص:** في مجلد بيانات التطبيق للمستخدم داخل `%APPDATA%` (مجلد باسم البرنامج؛ اكتب `%APPDATA%` في شريط عنوان المستكشف لفتحه). إزالة البرنامج لا تحذفها (هذا مقصود لحماية بيانات الزبون).
- نصيحة للزبون: يأخذ **نسخة احتياطية مشفّرة** دورياً من الإعدادات ← النسخ الاحتياطي.

## 9) مشاكل شائعة
| المشكلة | الحل |
|---|---|
| `The out directory was not found` | شغّل `npm run build` أولاً (أو استخدم `npm run dist` الذي يفعلها). |
| فشل التنزيل أثناء البناء | تأكد من الإنترنت/الجدار الناري، أعد `npm run dist`. |
| يطلب الترخيص أثناء التطوير | التطوير بـ `npm run electron:dev` لا يطلب ترخيصاً. إن ظهر، تأكد أنك لا تشغّل النسخة المثبّتة. |
| تحذير SmartScreen | وقّع الملف (القسم 6). |
| `npm install` يفشل | احذف `node_modules` و `package-lock.json` ثم أعد المحاولة، أو حدّث Node. |

## 10) تجربة النسخة المبنية دون تغليف
```
npm run build
set BADER_USE_BUILD=1 && npx electron .      (PowerShell:  $env:BADER_USE_BUILD=1; npx electron .)
```

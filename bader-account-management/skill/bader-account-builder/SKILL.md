# Bader Account Builder

Creates sibling programs of **Bader Account Management** (owner Bader Eddine Hamidane, Baderinfo, `baderinfo.com`) from a generic template that was derived from the real code and verified: `npm ci`, `tsc`, 23 unit tests, `next build`, a Playwright browser flow (Arabic RTL, encryption at rest, backup/restore, lock/unlock, i18n) and a real Electron flow (hardening, `app://`, relaunch persistence), also on an app generated by `new_app.py` + `add_module.py`. The user should be able to say "build a program similar to Bader Account Management for X" **without re-explaining how it works**: everything below is the explanation.

**Language**: the owner writes Arabic. Reply in Arabic (identifiers/commands stay Latin); UI default Arabic RTL; customer docs Arabic-first; code comments English.

## 0. What the program is (facts, not assumptions)
Desktop-only Windows program: Electron 44 serves a Next.js 16 static export (`out/`) through a private `app://<slug>` scheme. All user data lives in ONE encrypted blob in the renderer's localStorage: master password -> PBKDF2-SHA256 600k -> AES-GCM key kept only in memory; no recovery; throttled unlock; auto-lock (idle, minimize, screen lock, sleep). Pages: login/first-run, dashboard, accounts (+ cards, documents, contacts, subscriptions in the real app), password generator, security audit + AI assistant, security (sign-in) log, settings (profile, theme, auto-lock, backup, danger zone), licence page. Three languages ar/en/fr (Arabic default, RTL). Licence per device (Ed25519, lifetime offline), sales landing + WordPress plugin, installer by electron-builder (NSIS) and GitHub Actions. **The phone app and sync were removed (commit `844ee26`): never describe or build them unless explicitly asked; the history is only a note.**

## 1. SAFETY - do not break the existing apps (read first)
- **Never edit `bader-account-management/` (or BLR) to build another product.** Scaffold into a NEW folder outside them and outside this skill (`~/dev/<slug>`); `new_app.py` refuses otherwise. Report problems found in the originals, fix only when asked, in a separate change.
- This skill folder is read-only input: never run `npm install`/`build` inside it, never leave `node_modules/out/.next/dist` in repos or zips. Template `.ts/.tsx` files are stored as `*.ts.tpl`/`*.tsx.tpl` (renamed by `new_app.py`) because plain TypeScript inside an app's tree broke that app's `tsc`/`next build` (its tsconfig globs `**/*.ts`).
- Licence: edit only `bader-license/license-config.js`; never `device-id.js`/`license.js`. **Every program has its OWN `product_id`** (never `bader-account-management`, `blr-invoicing`, `bader-prog`, `bader-desktop-tool`).
- Never change the slug / `app://` host / vault key names after release (orphans customer data).
- No secrets in code, docs, logs or commits (the licence `public_key` and `server_url` are public values and stay). Do not commit/push unless asked.
- Be honest in every report about what was not verified (section 12).

## 3. What the template contains (`assets/template/`)
`electron-main.js` `electron-preload.js` `electron-ai.js` - `bader-license/*` + `tools/license-doctor.cjs` - `src/lib/*` (vaultCrypto, security, session, backup, securityAudit, aiTools, passwordStrength, print/printReport/reports, ...) - `src/store/useStore.ts` (single encrypted store with `// @module-*` markers) - `src/app/[locale]/*` (login, dashboard, accounts, generator, ai, security, settings, license-info) - `src/components/{layout,ui}/*` - `messages/{ar,en,fr}.json` - `tests/*` (vault, audit, i18n, licence) - `docs/*-AR.md` (build, licence, WordPress) - `.github/workflows/build-windows.yml` - fonts, icons, `CLAUDE.md`, `AGENTS.md`, `README.md`. Also `assets/landing/` (static sales page), `assets/wordpress/bader-landing/` (plugin) and `assets/module/*.tpl` (module generator templates). Details: `references/architecture.md`.

## 4. Architecture rules (summary; references/architecture.md)
- Static export only (no API routes); each page wraps itself in `<AppLayout>` (route guard + idle lock); client navigation keeps the key in memory, a reload locks.
- Main process owns network, licence and OS things; renderer sees only `baderAI`, `baderLicense`, `baderApp` (contextBridge); CSP `connect-src 'self'`, no external hosts, bundled fonts.
- `app://` handler: path-safe, `.txt` as `text/x-component`, SPA fallback to `ar/index.html`.
- One zustand store, `skipHydration`, `rehydrate()` after unlock; every collection in export/import/clear.

## 5. Crypto and security rules (references/crypto-security.md)
Never store the master password; key only in memory; random IV per write; throttling persists; change-password re-encrypts and keeps the log; dangerous actions re-verify the password; backups always `.bbak` (own password) and tagged with the program slug; secrets masked in lists, copied with auto-clearing clipboard, hidden in printouts unless the user agrees, **never** in AI payloads/logs/errors; AI summary is an allow-list with a unit test; honest limits (malware while unlocked, weak passwords, no recovery).

## 6. Add a module / page (references/add-module.md, recipes.md)
`add_module.py` with `--field "key|type|ar|en|fr"` (text, textarea, tel, email, url, password, number, date, select(...)) creates type + store slice + page + nav + dashboard card + print report + messages and wires backup export/import/clear. Then add business rules + tests. `recipes.md` has ready commands for cards, documents, contacts, subscriptions.

## 7. i18n and Arabic UX (references/i18n-arabic-ux.md)
Same keys in ar/en/fr (the i18n test enforces it), no hard-coded strings, logical CSS, Latin digits with `.num`, `dir="ltr"` for emails/ids, `dir="auto"` for user text, El Messiri bundled, semantic colour tokens (`bg-card text-fg text-muted border-border bg-primary`), confirm destructive actions, empty states with a primary action, honest warnings in Arabic.

## 8. Branding and licence (references/branding-licensing.md)
Decide name/slug/product id once; icons (`build/icon.png` tracked in git); accent; developer contact. Create the product in the licence dashboard (bind type device), keep the shared `server_url`/`public_key`, `max_offline_days: 0`, run `npm run license:doctor`, test a real code on Windows.

## 9. Build, CI, release (references/build-ci-release.md)
`npm run dist` = `next build` + `electron-builder --win --x64` (NSIS). Keep `files` list complete (`electron-*.js`, `bader-license`, `out`, `package.json`), everything in devDependencies. Workflow: windows-latest, Node 22, `npm ci`, typecheck, test, dist, artifact, `gh release create <slug>-v<ver>` (re-run safe). The real app has no workflow of its own: this one is derived from BLR's and was only YAML-checked. Unsigned = SmartScreen warning. Build locally in `C:\dev` (OneDrive locks NSIS output).

## 10. Landing page and WordPress (references/landing-wordpress.md)
Generated by `new_app.py`; engine is generic, copy is a DRAFT from Account Management that MUST be rewritten (`COPY-STATUS: DRAFT -> FINAL`, enforced by `--check --release`). Price/contacts via `site-config.js` or the WordPress settings screen. No invented reviews or claims. Plugin identifiers are renamed per program and zipped.

## 11. Pitfalls (references/pitfalls.md has 45)
Top ones: random-port origin loses the vault; `.txt` MIME; installer size/`files` list; `.gitignore` hiding `build/icon.png`; invalid-code = wrong server/key/product; `max_offline_days` 0; Tailwind v4 bare-triple tokens produce no utilities; `next/font/google` breaks offline builds; hard-coded locale/labels; backups must be origin-tagged; decorative settings; plain `.ts` files of a skill inside an app's tree break that app's tsc (template uses `*.ts.tpl`); Turbopack panics on symlinked `node_modules`.

## 12. QA and final report (references/qa-checklist.md)
Run `verify_app.sh --e2e`, read the screenshots (ar RTL, en, fr, dark, narrow), then report: created paths, passed checks with counts, **not verified**: Windows installer/NSIS, real activation against the dashboard, SmartScreen/signing, printers, GitHub Actions run, WordPress runtime. Leave no `node_modules/out/.next/dist` in repos or zips.

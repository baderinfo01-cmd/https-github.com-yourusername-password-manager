# ربط البرنامج بالترخيص (لوحة BaderProgLicense) — شرح مبسط ومفصل

## ⚠️ إن ظهرت رسالة «كود التفعيل غير صحيح» (حلّ المشكلة)
جرّبت **لوحتك BaderProgLicense فعلياً** مع برنامجك: التفعيل يعمل بنجاح (مدى الحياة، جهاز واحد، تجريبي يومين، ورفض منتج آخر). فالرسالة تعني فقط أن **البرنامج لا يكلّم لوحتك التي ولّدت الكود**. الأسباب بالترتيب:

| # | السبب | الحل |
|---|---|---|
| 1 | `server_url` في البرنامج يشير إلى لوحة قديمة (`.../apps-license/api.php`) والكود مولَّد من لوحتك الجديدة | في لوحتك: **الإعدادات ← معلومات تقنية ← عنوان التفعيل**، انسخه وضعه في `server_url` |
| 2 | `public_key` في البرنامج هو مفتاح اللوحة القديمة | في لوحتك: **الإعدادات ← مفتاح التوقيع ← نسخ المفتاح العام**، وضعه في `public_key` |
| 3 | الكود مولَّد لمنتج غير `bader-account-management` (مثل `bader-prog`) | صفحة **المنتجات ← إضافة منتج** بالمعرّف `bader-account-management`، ثم ولّد الأكواد لهذا المنتج |

> مفتاح التوقيع **يُولَّد جديداً** عند الإعداد الأول للوحة (وهو غير مفتاح لوحتك القديمة)، لذلك يجب تحديث `public_key` في البرنامج، وإلا ظهر «ملف الترخيص غير صالح».

**ثم نفّذ الأداة التي أضفتها لك:**
```
npm run license:doctor
```
تفحص المفتاح والعنوان والمنتج وتخبرك بالمشكلة بالعربية (لا تستهلك أي كود حقيقي). وجرّب عنواناً قبل تعديل الملف: `node tools/license-doctor.cjs https://موقعك.com/المجلد/api.php`

**على الجهاز الذي فشل فيه التفعيل:** يبقى فيه ترخيص قديم مخزَّن (كان سبب سطر «تم إلغاء هذا الترخيص»). احذف الملف `license.dat` من `%APPDATA%\bader-account-management\` ثم أعد فتح البرنامج وفعّل الكود الجديد. (بعد تغيير الإعدادات أعد بناء المثبّت `npm run dist` وثبّته من جديد.)

## الفكرة في أربعة أسطر
1. **أنت** تنشئ في لوحتك منتجاً اسمه `bader-account-management` وتولّد له **أكواد تفعيل**.
2. **الزبون** يثبّت البرنامج، فتظهر له نافذة **تفعيل الترخيص**، فيكتب كوده (مع اتصال بالإنترنت **لمرة واحدة فقط**).
3. لوحتك **تربط الكود بجهاز الزبون** وترجع للبرنامج ترخيصاً **موقّعاً رقمياً** يُحفظ على جهازه.
4. بعد ذلك يعمل البرنامج **مدى الحياة دون إنترنت**، و**لا يعمل على أي جهاز آخر ولا مع أي برنامج آخر**.

```
 لوحتك (baderinfo.com)  ──(مرة واحدة)──►  جهاز الزبون
   تولّد الكود                              يفعّل ويستلم الترخيص الموقّع
   تربطه بالجهاز                            ثم يعمل بدون إنترنت للأبد
```

## ما الذي يضمن الشروط التي طلبتها؟
| طلبك | كيف يتحقق | اختبرته آلياً؟ |
|---|---|---|
| يعمل مدى الحياة دون إنترنت | `max_offline_days: 0` في `license-config.js` (القيمة 0 = لا يتوقف أبداً). والترخيص الكامل بلا تاريخ انتهاء | نعم |
| لا يعمل على جهاز ثانٍ | الترخيص يحمل بصمة الجهاز، ويرفضه البرنامج على غيره (`wrong_device`). والخادم يرفض الكود إن استُعمل على جهاز آخر (`already_used`) | نعم (الجزء المحلي) |
| لا يصلح لبرنامج آخر | الترخيص يحمل معرّف المنتج، والبرنامج يرفض غير `bader-account-management` (`wrong_product`) | نعم |
| لا يمكن تزويره أو تعديله | توقيع Ed25519: يوقّعه خادمك بمفتاحه الخاص، والبرنامج لا يملك إلا المفتاح العام | نعم |
| نسخة تجريبية يومين | كود/ترخيص بتاريخ انتهاء بعد يومين، يتوقف بعدها حتى دون إنترنت | نعم (الجزء المحلي) |

الاختبارات المحلية في `tests/license.test.cjs` (`npm test`). وإضافةً لذلك شغّلت **ملفات لوحتك نفسها** (`api.php` و`lib.php`) محلياً وفعّلت عليها بالعميل الحقيقي، فنجحت كل السيناريوهات. **ما لا أستطيع اختباره:** لوحتك المنصوبة فعلاً على موقعك (عنوانها ومفتاحها)، لذلك استعمل `npm run license:doctor`.

> ملاحظة: إن أُلغي ترخيص (استرداد مثلاً) فإن البرنامج يتوقف في **أول مرة يتصل فيها الجهاز بالإنترنت** بعد الإلغاء (الفحص كل 12 ساعة عند توفر الاتصال). من يبقى دون إنترنت للأبد لا يصله الإلغاء، وهذا ثمن "العمل دون إنترنت".

## الجزء الأول: إعداد لوحتك (مرة واحدة)

### الخطوة 1 — ادخل لوحتك
ادخل لوحة BaderProgLicense على موقعك: `https://موقعك.com/المجلد/admin.php` (الملف `admin.php` وليس المجلد).

### الخطوة 2 — أنشئ المنتج
1. افتح صفحة **المنتجات** ← **إضافة منتج** (المنتجات الجاهزة `bader-prog` و`bader-desktop-tool` ليست لبرنامجنا، لا تستعملها).
2. **معرّف المنتج (Product ID):** اكتب بالضبط `bader-account-management` (حروف صغيرة وشرطات). يجب أن يطابق `product_id` في `bader-license/license-config.js`.
3. **نوع الربط:** اختر **«برنامج (.exe)»** (ربط بجهاز واحد، ويسمى `device`). هذا أهم إعداد.
4. أنواع التراخيص (Editions): أضف نوعاً واحداً مثل `lifetime = مدى الحياة`.

### الخطوة 3 — طابق المفتاح العام
1. في اللوحة: **الإعدادات ← مفتاح التوقيع** ← **نسخ المفتاح العام**.
2. افتح `bader-license/license-config.js` وتأكد أن `public_key` يطابقه تماماً. 
3. إن اختلفا فلن يقبل البرنامج أي ترخيص (`bad_signature`).

### الخطوة 4 — تحقق من العنوان
من اللوحة: **الإعدادات ← معلومات تقنية ← عنوان التفعيل** ← انسخه إلى `server_url` في `license-config.js` (ينتهي بـ `api.php`).

### الخطوة 5 — اضبط الملف (جاهز أصلاً)
```js
product_id: 'bader-account-management',
max_offline_days: 0,         // 0 = يعمل مدى الحياة دون إنترنت
check_interval_hours: 12,    // فحص الإلغاء كلما توفر الاتصال
```

## الجزء الثاني: توليد ترخيص كامل لزبون
1. لوحتك ← **ترخيص جديد** ← المنتج `bader-account-management`.
2. الخطة **مدى الحياة (lifetime)** (بلا تاريخ انتهاء)، واكتب اسم الزبون ثم **توليد الترخيص**.
3. انسخ الكود (شكله مثل `BAPP-XXXX-XXXX-XXXX`) وأرسله للزبون **وحده**. كود واحد لكل زبون.

### ماذا يفعل الزبون؟
1. يثبّت البرنامج (`Bader Account Management-Setup-3.0.0.exe`).
2. يفتحه ← تظهر نافذة **تفعيل الترخيص** ← يلصق الكود ← **تفعيل** (يحتاج إنترنت هذه المرة فقط).
3. تظهر رسالة نجاح ويفتح البرنامج. **من الآن بلا إنترنت، للأبد.**
4. من القائمة **معلومات الترخيص** يرى بياناته وبصمة جهازه.

## الجزء الثالث: ترخيص تجريبي لمدة يومين
الهدف: زبون يجرّب البرنامج يومين على جهازه ثم يتوقف تلقائياً (حتى دون إنترنت) إلى أن يشتري.

**لوحتك تدعم التجربة أصلاً:** الخطة **«تجريبي» (trial) = يومان** مدمجة، ويمنع الخادم أكثر من تجربة على الجهاز نفسه.
1. لوحتك ← **ترخيص جديد** ← المنتج `bader-account-management` ← الخطة **تجريبي** ← **توليد الترخيص**.
2. يفعّله الزبون كالمعتاد، فيعمل **48 ساعة من لحظة التفعيل** ثم تظهر له رسالة "انتهت صلاحية الترخيص" ويطلب كوداً جديداً.
3. عند الشراء: ولّد له كوداً **كاملاً (مدى الحياة)** ليفعّله.


> **تنبيه صريح:** انتهاء التجربة يُحسب بساعة جهاز الزبون. من يعيد ساعة الجهاز للخلف قد يطيل التجربة أثناء عدم اتصاله. ويُحدّه أن الخادم يُسأل عند أي اتصال. للنسخة التجريبية هذا مقبول عادةً.

## نقل الترخيص لجهاز جديد (الزبون غيّر حاسوبه)
1. افتح الكود في لوحتك ← اضغط **«نقل إلى جهاز جديد»**.
2. يُدخل الزبون **الكود نفسه** في الحاسوب الجديد (يحتاج إنترنت مرة واحدة).

## مشاكل شائعة
| الرسالة | السبب والحل |
|---|---|
| ملف الترخيص غير صالح (`bad_signature`) | `public_key` لا يطابق لوحتك (الخطوة 3) |
| هذا الكود خاص ببرنامج آخر | معرّف المنتج في اللوحة يختلف عن `bader-account-management` |
| تعذّر الاتصال بخادم التفعيل | لا إنترنت وقت التفعيل أو `server_url` خاطئ |
| تعذّر قراءة بصمة الجهاز | شغّل البرنامج مرة كمسؤول (Run as administrator) عند التفعيل |
| يعمل على جهازي دون ترخيص | هذا وضع التطوير (`npm run electron:dev`). النسخة المثبّتة تطلب الترخيص دائماً |

## نقاط يجب أن تعرفها بصدق
- **وضع التطوير** لا يطلب ترخيصاً، لكنه يتعطل تلقائياً في النسخة المثبّتة.
- **لا حماية مطلقة:** من يملك خبرة قد يعدّل أي برنامج يعمل على جهازه. النظام يمنع **النسخ والمشاركة العادية** وهو غالب القرصنة. وقّع الملف رقمياً (انظر `BUILD-EXE-AR.md`) لتقوية الثقة.
- **لا تعدّل** `device-id.js` ولا `license.js` فتعديلهما يبطل تراخيص الزبائن.
- صفحة الترخيص القديمة داخل البرنامج (التي كانت تقبل أي نص) حُذفت؛ التفعيل الحقيقي عبر نافذة Electron وخادمك فقط.

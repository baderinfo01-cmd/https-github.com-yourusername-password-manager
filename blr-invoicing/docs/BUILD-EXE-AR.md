# بناء ملف التثبيت `BLR-Setup-1.0.0.exe` — خطوة بخطوة

> ابنِ على **ويندوز** نفسه. ضع المشروع في مسار قصير بعيد عن OneDrive وسطح المكتب، مثل `C:\dev\blr`.
> (مجلد سطح المكتب المزامَن مع OneDrive وبرنامج الحماية يقفلان ملف المثبّت أثناء الكتابة فتظهر رسالة `output file is locked`.)

## 1) التجهيز (مرة واحدة)
1. ثبّت **Node.js 22 LTS أو أحدث** من https://nodejs.org (مهم: قاعدة البيانات المدمجة `node:sqlite` تحتاج 22.5+ في بيئة التطوير؛ أما المثبّت النهائي فيحمل محرك Electron الخاص به ولا يحتاج Node على جهاز الزبون).
2. افتح **PowerShell** داخل مجلد المشروع (Shift + كليك يمين ← Open PowerShell window here).
3. `node -v` ثم `npm install` (دقائق، يحتاج إنترنت).

## 2) أنشئ ملف التثبيت
```
npm run test       # (اختياري) اختبارات قاعدة البيانات والحسابات والترخيص
npm run typecheck  # (اختياري)
npm run dist
```
النتيجة:
```
dist\BLR-Setup-1.0.0.exe      ← هذا ما تعطيه للزبون
```
- إن ظهر `Can't open output file`: أضف المجلد لاستثناءات Defender (`Add-MpPreference -ExclusionPath "C:\dev\blr"`)، احذف مجلد `dist`، وأعد `npm run dist`.

## 3) جرّب قبل البيع (قائمة فحص)
1. ثبّت `BLR-Setup-1.0.0.exe` وشغّل البرنامج: تظهر نافذة **تفعيل الترخيص** (النسخة المثبّتة تطلب ترخيصاً دائماً).
2. فعّل بكود من لوحتك (منتج `blr-invoicing`، انظر `LICENSE-AR.md`) ← يفتح البرنامج.
3. أنشئ حساب المدير (أول مرة)، ثم **الإعدادات ← الشركة**: الاسم والشعار والعنوان وNIF/RC.
4. أضف عميلاً ومنتجاً، أنشئ فاتورة، سجّل دفعة، اطبعها (A4) واطبع إيصالاً حرارياً، وصدّر PDF.
5. أغلق البرنامج وافتحه: البيانات باقية وتحتاج الدخول بكلمة المرور.
6. **الإعدادات ← النسخ الاحتياطي**: احفظ نسخة بكلمة مرور ثم جرّب الاسترجاع.
7. افصل الإنترنت وافتح البرنامج: يعمل بلا مشاكل (الترخيص مدى الحياة).

## 4) أين تُحفظ بيانات الزبون؟
- قاعدة البيانات: `%APPDATA%\blr-invoicing\data\blr.sqlite` (أرقام الفواتير والعملاء والمنتجات…).
- نسخ احتياطية تلقائية يومية: `%APPDATA%\blr-invoicing\data\backups\` (آخر 14 نسخة).
- مفتاح المساعد الذكي (إن أُضيف): ملف مشفّر بحماية ويندوز داخل المجلد نفسه.
- إزالة البرنامج **لا تحذف** هذه البيانات (مقصود لحماية الزبون).

## 5) أيقونة البرنامج واسمه
- الأيقونة: `build/icon.png` (512×512) والشعار داخل الواجهة `public/brand/`. استبدلها بنفس الأسماء لتغيير الهوية.
- رقم النسخة: `package.json` ← `"version"` (يظهر في اسم المثبّت). غيّره في كل إصدار.
- معلومات المطوّر: `src/lib/brand.ts`.

## 6) التوقيع الرقمي (موصى به)
بدون شهادة Code Signing يعرض ويندوز تحذير SmartScreen عند أول تثبيت (More info ← Run anyway). لإزالته اشترِ شهادة توقيع ثم عيّن `CSC_LINK` و`CSC_KEY_PASSWORD` قبل `npm run dist`.

## 7) التحديثات
ارفع `"version"` ← `npm run dist` ← أرسل المثبّت الجديد؛ يُثبَّت فوق القديم وتبقى بيانات الزبون وترخيصه.

## 8) نقل بيانات برنامج الفواتير القديم (Smart Invoice System)
من phpMyAdmin صدّر جدولَي العملاء `biller` والمنتجات `items` بصيغة **CSV**، ثم في BLR: **العملاء ← استيراد** و**المنتجات ← استيراد** واختر الملف (يتعرّف على أسماء الأعمدة العربية والإنجليزية والفرنسية الشائعة: name, phone, email, address, price, cost, stock…).

## 9) مشاكل شائعة
| المشكلة | الحل |
|---|---|
| `The out directory was not found` | شغّل `npm run build` أولاً (أو `npm run dist`). |
| `output file is locked` | انظر القسم 2 (مسار قصير + استثناء Defender). |
| `npm install` يفشل | احذف `node_modules` و`package-lock.json` وأعد المحاولة. |
| يطلب الترخيص أثناء التطوير | `npm run electron:dev` لا يطلبه؛ المثبّت وحده يطلبه. |
